# VK Bot - Академия BVC

VK чат-бот для платформы дистанционного обучения "Академия BVC". Бот управляет процессом обучения, анкетирования и тестирования студентов.

## Функционал

### Для студентов

#### 1. Начальная анкета
- При первом запуске бота пользователь заполняет анкету из 10 вопросов
- Вопросы включают: ФИО, профессия, спортивный опыт, цели обучения и т.д.
- После заполнения открывается доступ к тестированию

#### 2. Тестирование (Курс 1)
- 20 вопросов с 3 вариантами ответов
- Проходной балл: 18 из 20
- Случайный выбор варианта из 3 доступных
- Перемешивание вариантов ответов

#### 3. Уведомление о практике
- После успешной сдачи теста появляется кнопка "Сдал(а) практику"
- При нажатии:
  - В базе данных устанавливается `practice_1 = True`
  - Менеджеры получают уведомление с гиперссылкой на пользователя
- **Важно:** Менеджер НЕ может открыть доступ к финальному анкетированию, пока `practice_X = False`

#### 4. Финальное анкетирование
- Доступно только если `access_survey_X = True` И `practice_X = True`
- Админ не может открыть доступ к финальному анкетированию, если практика не сдана
- Содержит 15 вопросов с ветвящейся логикой
- После завершения:
  - Пользователь получает поздравление
  - Данные сохраняются в `form_end_X`
  - Предлагается вращение "Колеса фортуны"

##### Структура финального анкетирования:
1. **Вопрос 1** (открытый): Время прохождения курса
2. **Вопрос 2** (Да/Нет): Были ли сложности
   - Если Да → Вопрос 2a (описание сложностей)
   - Если Нет → Вопрос 3
3. **Вопрос 3** (открытый): 3 важных открытия
4. **Вопрос 4** (Да/Нет/Не знаю): Предложения по улучшению
   - Если Да → Вопрос 4a (что улучшить)
   - Если Нет/Не знаю → Вопрос 5
5. **Вопрос 5** (открытый): 3 причины выбора BVC
6. **Вопрос 6** (открытый): 3 важные вещи в BVC
7. **Вопрос 7** (Да/Нет): Отметить тренера
   - Если Да → Вопрос 7a (кого отметить)
   - Если Нет → Вопрос 8
8. **Вопрос 8** (открытый): Достижение на курсе
9. **Вопрос 9** (открытый): Цели на 3-6 месяцев
10. **Вопрос 10** (рейтинг 1-10): Оценка курса
    - Если не 10 → Вопрос 10a (чего не хватило)
    - Если 10 → Вопрос 11
11. **Вопрос 11** (рейтинг 1-10): Рекомендация друзьям
    - Если не 10 → Вопрос 11a (чего не хватило)
12. **Вопрос 12** (Не против/Против): Публикация в соцсетях
13. **Вопрос 13** (Верно/Исправить ФИ/Исправить ФИ и падеж): Проверка данных для диплома
14. **Вопрос 14** (открытый): Исправление ФИ (если выбрано)
15. **Вопрос 15** (открытый): Исправление падежа (если выбрано)

#### 5. Колесо фортуны
- Доступно после завершения любого финального анкетирования
- После каждого финального анкетирования добавляется +1 вращение
- Кнопка колеса фортуны появляется в меню когда `fortune_wheel > 0`
- Кнопка показывает количество доступных вращений: "Колесо фортуны (N)"
- Призы и вероятности:
  - 2000 баллов - 1%
  - Вечерняя тренировка - 2%
  - Браслет - 5%
  - Брелок - 5%
  - Дневная тренировка - 5%
  - 1000 ₽ на мини-кемп - 4%
  - 3000 ₽ на большой кемп - 4%
  - 300 баллов - 10%
  - 200 баллов - 13%
  - 100 баллов - 14%
  - Ручка - 15%
  - Чек-лист по элементам - 15%
- Физические призы (Браслет, Ручка, Брелок) выдаются тренером
- Остальные призы - через менеджера

### Для менеджеров (USER_ADMIN)

#### Админ-панель
- **Скачать базу** - экспорт всех пользователей в XLSX файл
- **Обновление базы** - синхронизация с чатами VK
- **Открыть доступ к Анкете** - поиск пользователя и управление доступом

#### Управление доступом
1. Поиск пользователя по части имени (регистронезависимый)
2. Пагинация по 6 пользователей
3. Выбор курса (1-4)
4. **Проверка практики** - если `practice_X = False`, показывается ошибка, доступ НЕ открывается
5. Открытие/закрытие доступа к финальному анкетированию (только если практика сдана)
6. Автоматическое уведомление пользователя

### Условия доступа к финальному анкетированию

Для открытия доступа к финальному анкетированию курса X необходимо:
1. `practice_X = True` (пользователь нажал "Сдал(а) практику")
2. Админ выбирает курс X и нажимает "Открыть"

Если `practice_X = False`, админ видит ошибку: "Нельзя открыть доступ к финальной анкете! Практика не сдана"

## Правила написания кода

### ⚠️ ВАЖНОЕ ПРАВИЛО: Тексты сообщений

**Все текстовые сообщения, отправляемые пользователю, ДОЛЖНЫ храниться в файле `texts.json`.**

- Запрещено хардкодить тексты сообщений в коде (`app.py`)
- Все сообщения получаются через `TEXTS_DATA.get("key", "default")`
- Для подстановки переменных использовать шаблоны с `{variable}`
- При добавлении нового сообщения: сначала добавить в `texts.json`, потом использовать в коде

Пример:
```python
# ❌ Неправильно:
message = f"Пользователь {user_name} сдал тест!"

# ✅ Правильно:
# В texts.json: "test_passed_notification": "Пользователь {user_name} сдал тест!"
msg_template = TEXTS_DATA.get("test_passed_notification", "Пользователь {user_name} сдал тест!")
message = msg_template.format(user_name=user_name)
```

### Архитектура
- **Webhook**: Бот работает через VK Callback API (не long polling)
- **Async**: Весь код асинхронный (asyncio, aiohttp, asyncpg)
- **База данных**: PostgreSQL через asyncpg

### Стилистические правила

1. **Именование**
   - Функции: `snake_case` (например: `create_menu_keyboard`)
   - Классы: `PascalCase` (например: `VKAPI`, `Database`)
   - Константы: `UPPER_SNAKE_CASE` (например: `USER_SESSIONS`)

2. **Документирование**
   - Все функции имеют docstring в формате Google
   - Пример: `"""Create keyboard with menu buttons."""`

3. **Типизация**
   - Использовать type hints для всех функций
   - Пример: `def get_user(user_id: int) -> Optional[Dict]:`

4. **Обработка ошибок**
   - Все внешние вызовы оборачивать в try-except
   - Логировать ошибки с `flush=True`

5. **Клавиатуры**
   - Все клавиатуры создаются через отдельные функции
   - `one_time: False` для постоянных клавиатур
   - `inline: False` для клавиатур внизу экрана

6. **Сообщения**
   - Все тексты сообщений хранить в `texts.json`
   - Использовать шаблоны с `{variable}` для подстановки

7. **Сессии**
   - Временные данные хранить в словарях `*_SESSIONS`
   - Очищать сессии при выходе в меню

8. **Логирование**
   - Использовать `print()` с `flush=True`
   - Важные действия логировать с user_id

### Структура обработчиков

```python
# 1. Проверка авторизации
is_admin = (user_id == USER_ADMIN_ID)

# 2. Обработка кнопок (в порядке приоритета)
if text.lower() == "кнопка":
    # обработка
    return

# 3. Обработка текстовых ответов (если в сессии)
if user_id in SOME_SESSION:
    await handle_session(user_id, peer_id, text)
    return

# 4. Игнорирование неизвестных сообщений
print(f"Ignoring: {text}", flush=True)
```
